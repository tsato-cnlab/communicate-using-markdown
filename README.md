# Markdown でコミュニケーションする

_テキストを軽量に整形できる Markdown を使って、アイデアを整理し、共同作業を進めましょう。_

## ようこそ

GitHub はコードだけの場所ではありません。ソフトウェア開発で共同作業するためのプラットフォームであり、Markdown は issue やプルリクエストでのコミュニケーションをわかりやすく整理するための重要な方法の 1 つです。このコースでは、見出しをより効果的に作成・使用する方法、箇条書きで考えを整理する方法、チェックリストで作業の完了状況を示す方法を学びます。絵文字、画像、リンクを使って、Markdown で内容に奥行きを加えることもできます。

- **対象者**: 新しい開発者、GitHub を初めて使う人、学生。
- **学べること**: コメントやテキストファイルで、Markdown を使ってリスト、画像、リンクを追加する方法。
- **作るもの**: プレーンテキストファイルを更新して Markdown の書式を追加します。このファイルは、自分の GitHub Pages サイトを始めるためにも使えます。
- **前提条件**: このコースでは、ファイル編集に加えてプルリクエストも扱います。これらに慣れていない場合は、先に [GitHub 入門](https://github.com/tsato-cnlab/introduction-to-github) コースを受講することをおすすめします。
- **所要時間**: このコースは 1 時間以内で完了できます。

このコースでは、次のことを行います。

1. 見出しを追加する
2. タスクリストを作成する
3. コード例を追加する
4. 画像を追加する
5. プルリクエストをマージする

### このコースの始め方

演習を自分のアカウントにコピーします。その後、お気に入りの Octocat である Mona が最初のレッスンを準備するまで **約 20 秒** 待ち、**ページを再読み込み** してください。

<summary>うまくいきませんか？</summary><br/>

演習をコピーするときは、次の設定をおすすめします。

- owner には、リポジトリを置く個人アカウントまたは Organization を選びます。
- プライベートリポジトリでは [Actions の実行時間](https://docs.github.com/en/billing/managing-billing-for-github-actions/about-billing-for-github-actions) が消費されるため、パブリックリポジトリの作成をおすすめします。

20 秒待っても演習の準備ができない場合:

1. 新しいリポジトリが作成されたら、約 20 秒待ってからページを再読み込みします。
2. リポジトリ内に作成された issue の手順に従います。
3. ページが自動的に更新されない場合は、[Actions](../../actions) タブを確認してください。
   - ジョブが実行中かどうかを確認します。単に少し時間がかかっているだけの場合があります。
   - 失敗したジョブが表示されている場合は、issue を作成してください。バグを見つけてくれてありがとうございます！
